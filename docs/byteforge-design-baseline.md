# ByteForge Design Baseline

版本：2026-06-02
状态：正式设计基线

## 定位

ByteForge 首页定位为个人技术博客和作品集的第一视觉入口。视觉关键词为数字熔炉、终端系统、数值流、粒子光场、极客导航。页面不做传统营销式首页，首屏直接呈现可用的品牌动效系统。

## 品牌文案

品牌标识：

```text
<B/> THE BYTE FORGE
byteForge()
```

浏览器图标：

- 使用透明背景，不使用方形底板。
- 图形为中心熔炉光核加两段不闭合轨道光点。
- 色彩延续 Gruvbox 橙、羊皮纸白、青绿色和暗金色，保证浏览器标签页小尺寸下仍然醒目。

核心标语：

```text
>_ SYSTEM INIT... 构筑于代码与协议之上的数字熔炉。
```

交互提示：

```text
>_ 等待指令：请锁定节点以解析轨道数据_
```

终端导航：

```text
user@forge: ~/logs
~/deployments
/.search
```

内容入口：

```text
Logs
Dev and AI
Snippets
Academic
Deployments
Search
```

## 视觉系统

主配色采用 Gruvbox Dark 风格：

```text
bg0      #1d2021
bg       #282828
bg1      #3c3836
fg       #ebdbb2
orange   #fe8019
green    #b8bb26
aqua     #8ec07c
yellow   #fabd2f
blue     #83a598
purple   #d3869b
red      #fb4934
```

字体使用严格等宽栈：

```css
'Fira Code', 'JetBrains Mono', 'Sarasa Gothic SC', 'Microsoft YaHei Mono', monospace
```

色温与清晰度：

- 页面整体保持中性深色，不允许回到大面积偏黄、偏灰的雾化底色。
- 中心光场可以明亮，但暖色扩散必须收窄，不能把整页染成黄色。
- 首页背景以冷中性深色和少量青绿色环境光为主，橙黄只允许作为局部核心和少量强调色。
- 主标题 `byteForge()` 保持锐利，不使用大范围白色光晕；橙色 `byte` 仅保留轻微短距离 glow。
- 数值流允许发光，但 glow 需要收紧，避免文字边缘糊成一片。
- CRT、grain 和暗角只作为极轻质感层，不能造成灰蒙蒙的遮罩感。
- 首屏显影动画允许短暂 blur，但最终稳定态必须清晰，不得保留可感知的整体模糊滤镜。
- 左上品牌区必须保持阅读清晰，但不使用独立黑色底色、渐变底色或卡片背景；通过数值流透明度、文字锐度和层级控制避免视觉混叠。
- 中心光源保持原有柔和熔炉光核质感，不使用硬圆盘或圆环；中心光点可以适度放大，外围光谱扩散需要近似圆形，允许扩大到首屏大范围区域，但必须低饱和递减，不能把整页染黄。
- 中心光源的启动和呼吸过渡使用慢速自然曲线，允许轻微先扩后收，但不能出现突兀跳变或硬闪。

## 首屏结构

冻结以下层级：

1. 背景数值流：多轨道、无边缘光带、持续无缝移动。
2. 随机星芒：分布在全屏，使用短暂 steps 闪烁。
3. 中心光场：明亮恒星光晕，强度由中心向边缘递减，不使用圆环。
4. 边缘撞入粒子：从四周进入中心，尾迹在进入中心前收短并消失。
5. 入口光点：11 个旋转入口节点，作为后续功能入口。
6. DOM 文案：左侧品牌，右上状态条，右下终端导航。
7. 质感层：CRT 扫描线、微弱 grain、暗角聚焦。

## 动效规则

Boot Sequence：

- 首次进入显示启动日志。
- 从其他页面返回时不显示 Boot Sequence。
- 日志下方有窄块状闪烁光标。
- Boot 到主视觉使用柔和退场：日志上移消散、扫描线掠过、轻微上滑、模糊淡出。

主视觉显影：

- 数值流先显影。
- 星芒和中心光云随后显影。
- 撞入粒子和入口光点再浮现。
- 品牌与导航最后进入。

鼠标动态：

- 使用分层视差。
- 数值流轻微反向移动。
- 星芒、粒子层、入口光点和中心光源按不同幅度跟随鼠标。
- 使用 requestAnimationFrame 和慢速插值，避免抖动。

入口光点：

- 光点样式和基础旋转速度保持稳定。
- 鼠标悬停当前光点时，仅降低当前光点动画速率。
- 鼠标离开后恢复原速。
- 点击时使用 `.is-locked` 展示标签，避免原生按钮焦点造成反向闪现。
- 键盘访问保留 `focus-visible` 状态。
- 不劫持浏览器默认 `Tab` 顺序；主题按钮、导航链接和入口光点都必须可键盘到达。
- 入口光点的 `aria-label` 使用真实业务名称，不使用无语义的序号。
- 入口状态由 `data-state` 表达，至少包含 `ready`、`beta`、`future`、`disabled`。
- `future` 和 `disabled` 状态不可点击；`ready` 和 `beta` 状态可绑定内容路由。
- 背景音乐开关位于终端导航栏，默认关闭，点击后播放或暂停 `public/audio/ink-wash-terminal.mp3`。
- 音乐按钮必须保留 `aria-pressed` 和明确的 `aria-label`，不得依赖自动播放。

内容面板：

- 同站内容链接使用 SPA 导航，保留浏览器前进后退。
- 带 hash 的内容链接必须能定位到对应条目，不得被空拦截。
- `/search/?q=` 必须能初始化搜索结果，输入框变化同步 URL 查询参数。
- `/academic` 使用 `data-route-theme="ink"`，表现为现代纸页、水墨纹理、墨色正文和朱砂强调。

## 禁止回退项

以下方案已明确废弃，不应恢复：

- 中心熔炉圆环设计。
- 黑蛇式背景。
- 旋转流星层 `.core-comets`。
- 入口光点父层 brightness 过冲显影。
- 点击入口光点时使用原生 focus 作为显示状态。
- 流星到中心后可见回拉或后移。

## 验收标准

- 页面无 JS 异常。
- Boot 首次进入显示，返回页跳过。
- 入口光点数量为 11。
- 边缘撞入粒子数量为 8。
- `.core-comets`、`.core-comet`、`.comet-tail` 不存在。
- 鼠标视差变量能随 pointermove 更新。
- 入口光点 hover 降速到 0.18，离开恢复到 1。
- 中文文案无乱码。
- 移动端无横向溢出。
- `/logs/`、`/deployments/`、`/search/`、`/dev-ai/`、`/snippets/`、`/academic/` 可直接刷新访问。
- `og-image.svg` 存在于静态资源目录并随构建产出。
- `src/main.js` 只做模块装配；内容数据位于 `src/data/`，交互逻辑位于 `src/modules/`，样式位于 `src/styles/`。
